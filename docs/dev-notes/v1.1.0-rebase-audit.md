## Decisions strategiques finales (fin de session 1)

### 1. kleos-mcp refonte = ABANDONNE

Decision : revert le commit 4743780 en session 2.

Justification :
- Refonte locale de ~2000 lignes (architecture standalone : Database, LocalModelClient,
  modules auth/tools/transport) vs upstream simple proxy HTTP (~750 lignes).
- L'operateur **n'a jamais teste kleos-mcp** en prod a date 2026-05-13. Utilise
  actuellement uniquement kleos-cli et kleos-server. En cours de config sur
  kw/ksh/kr/kleos-cred/kleos-credd.
- Garder la refonte = payer le cout de maintenance (conflits massifs a chaque release
  upstream) sans aucun benefice fonctionnel actuel.
- Si kleos-mcp devient necessaire plus tard : essayer d'abord la version upstream
  (proxy HTTP). Si elle manque quelque chose, ajouter des patches minimaux cibles,
  PAS une refonte parallele.

### 2. TAKE_UPSTREAM (44 fichiers) corrige un bug SQL latent

Decouverte session 1 : les migrations tenant v22-v40 (memories_user_id_drop, etc.)
sont identiques entre local/patches et upstream et suppriment la colonne `user_id`
des tables tenant. **MAIS** le code SQL local de `kleos-lib/src/{intelligence/*.rs,
episodes.rs, facts.rs, pack.rs, services/broca.rs, graph/*.rs}` continue de
referencer `user_id` dans des WHERE clauses.

Upstream a corrige ces requetes dans les commits :
- a0880ee `fix(kleos-lib): resolve tenant schema drift causing MCP 500s`
- a798947 `fix(kleos-lib,kleos-server): drop user_id from all tenant-scoped SQL queries`

Notre kleos-server LXC 121 tourne probablement avec ces bugs SQL latents qui
retournent `no such column: user_id` sur certains chemins (sans doute features
non utilisees au quotidien). **TAKE_UPSTREAM fixe ces bugs en passant**.

Verification post-deploy obligatoire : kleos-server doit demarrer sans erreur
de migration sur LXC 121.

### 3. Patches restants : 12 GARDE (Familles A et B)

3 familles de patches identifiees :
- **Famille A** (cfg windows/unix isole) : Patches 1, 2, 5A, 5B, 9, 10. Cout
  maintenance trivial, upstream Linux-first ne les absorbera jamais. GARDE.
- **Famille B** (modif logique fine) : Patches 7, 8A, 8B, 8C, activity kleos-cli.
  Petits diffs, candidats potentiels a PR upstream plus tard. GARDE.
- **Famille C** (refonte parallele) : kleos-mcp. ABANDONNE.

Critere pour decision future de garder un patch local :
1. Resout un besoin **structurel** non couvert par upstream
2. Est **isole** ou **minimal** (faible probabilite de conflit recurrent)
3. Ne peut PAS etre reproduit cote config/env sans patcher le code

## Resume des decouvertes

1. **Refonte locale majeure de kleos-mcp non documentee dans `local-patches.md`** :
   upstream a kleos-mcp = simple proxy HTTP vers kleos-server. Local a une refonte
   standalone avec sa propre `Database`, son propre `LocalModelClient`, et un decoupage
   modulaire complet (`auth.rs`, `tools/{admin,context,graph,intelligence,memory,services,skills,structural}.rs`).
   12 fichiers concernes, ~2000 lignes. **Decision : ABANDONNE (cf. section ci-dessus).**

2. **Faux positifs dans `kleos-lib/src/intelligence/*.rs`** : ce que le diff montre comme
   "modifs locales" est en realite la version pre-fix d'upstream. Upstream a recemment
   (commits a798947, 24387c8) supprime `user_id` des requetes SQL tenant-scoped. Local
   est en retard. **TAKE_UPSTREAM** pour ce lot.

3. **kleos-client/*** : upstream a un module complet, local en a une version vide ou
   absente. Upstream est la reference, on prend `TAKE_UPSTREAM`.
